## 2. Fix (green): `0648760`
- **Links:** `escaping_links(root, relatives=None)` checks every path prefix, so a link to a folder is reported even
  when `git ls-files` lists the files below it, as git for Windows does for a junction. Links and junctions count;
  a target is resolved with `realpath` and never read. `check_links` runs on `git ls-files --cached --others
  --exclude-standard` of the checkout before the worktree is created, and on a walk of the worktree after the input
  files are written (`.git` not entered). The version check now runs after both scans, so an escaping link means the
  CLI is never started.
- **Git metadata:** `git_metadata_snapshot` reads `--git-common-dir` and adds `.git/config`, `.git/info/attributes`
  and every file of `.git/hooks/` to `tree_snapshot`, keyed `.git/...`, with a SHA-256 or `None` when missing.
- **CLI and inputs:** `cli_snapshot(cli)` hashes each argv file (the first also found on PATH), resolved through its
  links, plus, for the locked CLI, every file under `scripts/ci/claude-cli/node_modules/@anthropic-ai/`.
  `folder_snapshot` hashes `ci-out/review/input/`. Both are taken before the version check and compared before each
  pass. A difference exits 2 and names the paths.
- **Key-free children:** `run_git` and `ac_audit_summary` use `tool_environment()`. `child_environment()` (with the
  key and the scrub flag) is used only by `check_bubblewrap`, `check_version` and `run_pass`.
- **Head commit:** `pinned_head` validates `PF_REVIEW_HEAD_SHA` (format, then `rev-parse`, then `merge-base
  --is-ancestor <sha> HEAD`); a mismatch with the resolved range head fails closed; `create_worktree(repo, head)`
  adds the worktree at the range head instead of `HEAD`.
- The module docstring describes all of the above.

## 5. Only a real CI run can prove
| Item | Why |
|---|---|
| The CLI's bubblewrap placeholders in the worktree are not links that resolve outside it | The link scan runs before pass 1 only, so placeholders created during a pass are not scanned. If the pinned CLI ever left a link in the checkout itself, the run would fail closed |
| `cli_snapshot` covers the file the locked CLI really runs (`node_modules/.bin/claude` → the `@anthropic-ai/claude-code` entry, plus the platform package binary) | The test uses a synthetic layout; `npm ci` on Linux makes the real one |
| Hashing the CLI package files twice per pass stays within the job timeout | The native binary is large; not measured here |
| `git rev-parse --path-format=absolute --git-common-dir` on the runners (git 2.31 or later) | Ubuntu 24.04 and the bookworm image ship newer git, but this was not run there |
| The PR head SHA is reachable from the merge commit in the GitHub checkout (`fetch-depth: 0`) and in a GitLab merged-results pipeline (`GIT_DEPTH: "0"`) | It depends on the platforms' refspecs. On a plain GitLab MR pipeline `CI_MERGE_REQUEST_SOURCE_BRANCH_SHA` is empty, and `CI_COMMIT_SHA` is the source head |
| The untracked-file scan of the real checkout does not trip on files earlier CI steps leave outside `.gitignore` | Only links that escape fail the run. Links that stay inside are allowed |

## Lesson
A sandbox boundary drawn by path rules (`Read(./**)`) is only as good as what the path names: a link turns an inside
path into an outside read. Check what the paths resolve to, and hash everything the next step trusts (the CLI, its
inputs and `.git` metadata), not only the working tree.
