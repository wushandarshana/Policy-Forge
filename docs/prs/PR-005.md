# PR-005: commit-guard hook splits commands quote-aware (`fix/hook-quoted-separators` → `dev`)

| | |
|---|---|
| Branch | `fix/hook-quoted-separators` → `dev` |
| Date | 2026-10-28 |
| Found by | The live hook during `/release v0.1.0`. It blocked the legitimate `git merge --no-ff dev -m "…; …"` because the `;` characters inside the quoted message were treated as command separators. |

## Fix
`command_segments()` tokenizes with `shlex` (`punctuation_chars`) first, then splits only on `;`, `&&`, `||`, `|`, `&`
and newlines that appear outside quotes. Unbalanced quotes fall back to the old naive split, which is conservative.
Knowledge deposit: KD-012.

## Evidence
- **Red:** the new regression case (the exact release command) fails on the old hook with exit 2.
- **Green:** `test_hooks.py` passes all 145 cases (138 previous + 7 new). The new cases cover quoted separators, which
  must be allowed, and real separators that still get blocked: `;`, `&&`, a newline, and a merge followed by a commit.

No application code changed.
