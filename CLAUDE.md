# PolicyForge — Root CLAUDE.md

Policy issuance & lifecycle management platform for **Horizon Insurance** (capstone BC-AINE-004).
Products: **Term Life, Motor, Household**. Lifecycle: quote → application/KYC → underwriting → issuance →
endorsement → renewal / lapse → cancellation.

This file holds the rules for the whole repository. More specific rules live in module- and folder-level
`CLAUDE.md` files (see [`AGENTS.md`](AGENTS.md)). When rules conflict, the more specific file wins, except for the
**Non-negotiables** below, which always apply.

## Non-negotiables

1. **No hand coding.** All production code, tests and migrations are generated by Claude Code agents.
   Humans edit only substrate: `specs/`, `docs/`, `CLAUDE.md`, `AGENTS.md`, `.claude/**`, `plugin.json`, `.mcp.json`.
2. **Spec is truth.** If code and a spec disagree, the spec wins. Change the spec deliberately first (separate commit),
   then regenerate the code. Never change behaviour that a spec AC pins without updating the spec.
3. **PR-only merge, branching strategy `feature → dev → main`.** `main` is production-ready and `dev` is the
   integration branch. Both are protected: never commit, rebase or force-push them. All work happens on `feat/*`,
   `fix/*` or `chore/*` branches cut from `dev`. When a feature is done and the review agents pass, `/pr` merges it
   into **`dev`** with `--no-ff`. After QA and all testing pass on `dev`, `/release` merges `dev` into **`main`** with
   `--no-ff`. Remote: `origin` = https://github.com/wushandarshana/Policy-Forge. GitHub rulesets require **pull
   requests** into `dev` and `main`. `/pr` and `/release` open them with `gh pr create`, and they are merged with
   "Create a merge commit" only (no squash or rebase). The `no-direct-main-commit.sh` hook guards the local side.
4. **Synthetic data only.** Use dummy names, IDs, Aadhaar/PAN-shaped values (e.g. `XXXX-XXXX-1234`, `ABCDE1234F`).
   Never use real customer or Virtusa data.
5. **Money is fixed-point (NFR-01).** Use `BigDecimal` for premium, refund, sum insured, rates and fees, with scale 2
   and `RoundingMode.HALF_UP` at the boundary and scale 10 for intermediate steps. Never use `double`/`float`.
   The `premium-precision-check.sh` hook and ArchUnit enforce this.
6. **Append-only records (NFR-02, NFR-05).** Don't update or delete policy versions, endorsements, status transitions,
   refund records, audit entries or rule-set versions. A new fact is a new row. Never edit an existing Flyway migration
   (`V*__*.sql`) or published rule file (`rules/<product>/v<N>.json`); add a new one instead.
7. **No PII in logs (NFR-03).** Never log Aadhaar, PAN, health declarations, date of birth or full name. Log IDs only.
   `pii-redaction-check.sh` enforces this.
8. **Every AC has a test.** Each test names the **full sub-criterion**: `@Tag("AC-NN")` plus
   `@DisplayName("AC-NN.M: …")` (JUnit), or `test('AC-NN.M: …')` (Vitest/Playwright). A test that names only `AC-NN`
   doesn't cover any `AC-NN.M` (`/ac-coverage` reports it as PARENT-ONLY, which counts as a gap).

## Stack

| Layer | Choice |
|---|---|
| Backend | Java 21, Spring Boot 3.x, Maven wrapper (`./mvnw`) |
| Persistence | H2 (file/in-memory), Spring Data JPA, Flyway migrations |
| Frontend | React 18 + Vite + TypeScript, served by Spring Boot in the packaged app |
| Tests | JUnit 5, AssertJ, Spring Boot Test, ArchUnit, JaCoCo; Vitest; Playwright |
| CI | GitLab CI (`.gitlab-ci.yml`, added in Sprint 5) with a Claude Code review stage |
| MCP | Playwright MCP (`.mcp.json`), used by the evaluator for live UI checks |

## Architecture (see `docs/architecture.md`)

Strict layering, enforced by ArchUnit tests in `backend/src/test/java/com/horizon/policyforge/architecture/`:

```
web (controllers, DTOs)  →  service (use cases, transactions)  →  repository (Spring Data)  →  domain (pure rules)
```

- `domain` is pure Java with no Spring, JPA or web imports. All business rules live here.
- `service` orchestrates. It owns `@Transactional` boundaries and audit writes.
- `web` checks authentication and roles (NFR-04) and maps DTOs. It has no business logic.
- `repository` holds JPA entities and Spring Data repositories. Append-only repositories expose no delete methods.

## Workflow

1. Read the relevant spec in `specs/`, then `/sprint specs/<feature>_spec.md` (agent-harness) to plan and get a contract.
2. Use TDD (`docs/tdd.md`): commit a failing AC-tagged test (`test: red …`), then the implementation
   (`feat: green …`), then cleanup (`refactor: …`).
3. The evaluator runs `./mvnw verify`, `npm test` and Playwright MCP against the running app.
4. The `security-reviewer` and `test-engineer` agents review the work, then `/sprint-archive` and `/pr` merge.
5. Record recurring mistakes in `docs/knowledge-deposits.md` and encode them into a hook, skill or CLAUDE.md rule.

## Commands

| Task | Command |
|---|---|
| Run the app | `cd backend && ./mvnw spring-boot:run` → http://localhost:8080 |
| Backend tests and coverage | `cd backend && ./mvnw verify` (JaCoCo → `backend/target/site/jacoco/`) |
| Frontend unit tests | `cd frontend && npm test` |
| E2E tests | `cd frontend && npx playwright test` |
| AC coverage audit | `/ac-coverage`, or `python scripts/ac_audit.py` |

## Debugging: environment first

When something fails, check the environment before changing code: JDK version and `JAVA_HOME`, `PATH`,
line endings on `.sh` hooks (must be LF), ports in use, stale `target/`, and Node version. Record the resolution in
`docs/post-mortems/`.
